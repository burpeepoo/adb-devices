# ADB Manager Auto Update Design

## Goal

ADB Manager should notify users when a newer released version is available, let them choose whether to download it, show download progress, install the update, and relaunch when installation is complete.

## Release Channel

Use the existing public GitHub repository as the stable update channel:

```text
https://github.com/burpeepoo/adb-devices/releases/latest/download/latest.json
```

The app checks this static updater JSON. Release assets remain on GitHub Releases, matching the current packaging workflow.

## Important Rollout Constraint

Versions that are already installed today do not have updater code. Users must manually install the first updater-enabled release once. Versions after that can be detected and installed by the app.

## Security Model

Tauri updater signatures are separate from Apple Developer ID signing and notarization.

- The updater public key is safe to commit in `src-tauri/tauri.conf.json`.
- The updater private key must stay secret.
- Local macOS release builds read the private key from a local ignored file or environment.
- GitHub Actions Windows builds read the private key from GitHub Secrets.
- Losing the private key prevents future updates for already-installed updater-enabled builds.

## Client Experience

The app checks for updates once shortly after startup.

If an update is available:

- Show a compact modal with the new version and release notes when available.
- Let the user choose `Later` or `Download and install`.
- Show download progress while the update downloads.
- After installation, relaunch the app.

The Settings dialog also includes a manual `Check for updates` button with clear states:

- checking
- no update
- update available
- downloading
- installed and relaunching
- failed with retry option

The app should not silently install updates while the user may be in the middle of an ADB workflow.

## Platform Scope

Initial scope:

- macOS Apple Silicon
- macOS Intel
- Windows x64

No Linux updater support is required for this app.

## Release Assets

Formal releases continue to include first-install assets:

- `ADB_Manager_X.Y.Z_aarch64.dmg`
- `ADB_Manager_X.Y.Z_x64.dmg`
- `ADB.Manager_X.Y.Z_x64-setup.exe`
- `ADB.Manager_X.Y.Z_x64_en-US.msi`

Updater releases additionally include platform update bundles and signatures generated by Tauri:

- macOS `.app.tar.gz`
- macOS `.app.tar.gz.sig`
- Windows installer updater signature files
- `latest.json`

The `latest.json` file must include:

- `version`
- `notes`
- `pub_date`
- `platforms.darwin-aarch64.url`
- `platforms.darwin-aarch64.signature`
- `platforms.darwin-x86_64.url`
- `platforms.darwin-x86_64.signature`
- `platforms.windows-x86_64.url`
- `platforms.windows-x86_64.signature`

## Implementation Units

### Tauri Configuration

Add updater configuration to `src-tauri/tauri.conf.json`:

- `bundle.createUpdaterArtifacts`
- `plugins.updater.pubkey`
- `plugins.updater.endpoints`
- `plugins.updater.windows.installMode`

### Rust App Setup

Register the updater plugin in `src-tauri/src/lib.rs`.

### Frontend Updater UI

Create a small updater module and UI component:

- wraps `@tauri-apps/plugin-updater`
- calls `check()`
- stores update metadata
- handles `downloadAndInstall()`
- uses `@tauri-apps/plugin-process` for relaunch
- renders startup prompt and Settings manual check states

### Release Tooling

Add a script that can assemble `latest.json` from generated release artifacts and `.sig` files.

Update release documentation so future releases include:

- `TAURI_SIGNING_PRIVATE_KEY`
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` if the key has a password
- uploading updater bundles/signatures
- uploading `latest.json`

## Verification

Run:

```bash
npm run build
cd src-tauri && cargo fmt -- --check
cd src-tauri && cargo test
graphify update .
```

Then validate updater artifacts during the next real release by installing the first updater-enabled build and confirming it detects a later test release.
